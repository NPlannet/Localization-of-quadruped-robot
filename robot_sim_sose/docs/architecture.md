# Project Architecture

## Data flow

```text
XGO controller -> xgo_driver_bridge -> /imu/data, /odom, /battery_state
                         ^
                         └----------- /cmd_vel

LD19 -> /scan -> dynamic_scan_filter -> /scan_filtered
              \                         /
               -> selected SLAM method -> /map, map -> odom

camera_ros -> image + CameraInfo -> RTAB-Map or Foxglove
```

The raw scan is never overwritten. A mapper consumes either `/scan` or
`/scan_filtered`, allowing paired evaluations from the same recording.

## Coordinate frames

The required transform chain is:

```text
map -> odom -> base_link -> laser/camera
```

- `map`: globally corrected SLAM frame.
- `odom`: locally continuous frame from applied velocity and XGO orientation.
- `base_link`: robot body frame.
- Sensor frames: fixed transforms below `base_link`.

XGO odometry integrates commanded velocity; it is not ground truth. Slip,
carrying, and uncommanded motion are not measured directly. SLAM corrects part
of this error through `map -> odom`.

## Runtime modes

| Mode | Entry point |
| --- | --- |
| Gazebo | `xgo_description simulation.launch.py` |
| Desktop bag replay | `xgo_description bag_replay*.launch.py` |
| Physical robot | `xgo_driver_bridge robot_sensor_bringup.launch.py` |
| Headless Pi benchmark | `scripts/robot_bag_benchmark.sh` |
| Repeated benchmark matrix | `scripts/run_benchmark_matrix.py` |

Build products (`build/`, `install/`, and `log/`) are generated by colcon and
are not source code.
